## 本轮修复

| 问题 | 实现及验证边界 |
| --- | --- |
| 证据不足回答把无关引用当作缺失数据的证明 | 引用支持实际检查到的来源标题；随后说明授权摘录不能证明所求模块数量。没有可引用标题时不虚构引用，不输出禁止数量。G1 与 G2 使用同一生成逻辑。 |
| 普通比较只检索排名片段，遗漏范围条款 | 将已有受控、有界原文读取扩展到明确选择资料的范围比较、状态及能力摘要。最多四份资料、每份最多八块，仍受现有工具/检索预算和当前来源守卫约束。 |
| 范围、状态和计划时间被模型自由解释 | 对明确命名 Skill 的比较，从真实表头/行读取状态与 Target Week，直接引用范围排除条款和对应表格；状态冲突或缺少所请求行时回退，不凭空宣布交付。模型答案提示也明确编号只支持相应摘录。 |
| 状态问答被误判为查找文档 | 对明确请求记录状态的内容问题纠正 document_search 为 knowledge_qa，读取真实受控原文；查找相关文档仍保持文档检索。新增原问题及文档列表反例回归。 |
| 新原生表头加粗、重复 ID 和空状态 | 解析格式化表头，支持自然语言 statuses；相同 ID 的不同能力各自保留。空状态输出 not recorded，不从邻行推断。G1 复用既有 Research 行解析器，模型仅翻译能力名称。 |
| 共用翻译可能跨越权限调用边界 | 用 request-local `model_access_scope(check_model_access)` 继承 Chat 的来源守卫；不存在共享 last-request 状态或正向授权缓存。新增回归验证翻译前检查仍发生。 |
| 历史会议问题被写成当前问题 | 能力摘要明确区分会议记录的问题/行动项与当前 Goals 状态；Finished 表格本身不能证明历史证据链接问题后来解决。 |
| 评分器把正确原生块判作不在正文 | 原生 parser 会移除注释或规范表格，Reader 会移除相邻块重叠。评分器核对冻结原始块、连续派生上下文及实际 anchor；错误块定位、伪造追加仍拒绝。原评分不覆盖。 |
| Qwen 裁判非法 JSON/检查项不一致 | 显式关闭 Qwen 评分请求的 provider thinking，给出与检查项数量一致的对象模板；保留严格类型和明确理由/布尔矛盾校验。仅结构异常重试一次，有效负评分不重试。记录实际请求参数和所有异常原文。 |
| 接口失败只保存 HTTP 403，导致继续无效评测 | 保存经过格式校验的 provider error code，保留已有尝试，不重试 provider 拒绝；不保存可能包含敏感内容的错误消息。续跑器可据此暂停。 |
