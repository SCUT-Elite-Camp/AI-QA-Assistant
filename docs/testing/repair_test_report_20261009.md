## 1. 文档目的与结论

当前本地版本保留了 Deep Research，普通英文问答与研究任务的核心链路已完成针对性修复和复测。18 道英文问题在 G1、G2 两种模式下各执行三次，共 108 个验收坐标，最终台账中的记录均成功执行并具有有效质量评分。原始严格评分通过 98 份，其余 10 份经过原文人工核对后通过；人工判定未覆盖或改写原始评分。

本轮已定位的主要答案、引用、研究衔接及历史操作缺陷已修复并复测。文件上传完整链路、管理后台、全部权限角色组合及完整设备矩阵仍未全面验收，因此本说明不代表整个产品已达到所有缺陷清零或生产发布标准。

## 2. 当前版本组成与交付状态

### 2.1 分支与功能基础

直接以 optimization 替换本地版本时，研究模块和研究接口缺失，无法满足 G2 测试要求。最终采用 agent-dev-infra 为基础合并 optimization 的方式，在保留 Deep Research 的同时接入优化内容。

当前版本的核心功能包括：

- G1/Fast：英文提问、知识库检索、流式回答、事实引用、原文查看及历史保存。
- G2/Deep Research：资料选择与冻结、任务创建、研究计划编辑和审批、执行进度、证据与发现核验、报告生成、研究追问及 Markdown 下载。
- 聊天操作：编辑、重新生成、复制、收藏及刷新后的答案与引用恢复。
- 用户界面：可折叠实时推理浮窗、右侧问题导航、Dashboard、Settings、Topics 和证据来源看板的主题适配。

本轮修改尚未执行新的 Git 提交或推送。远端分支或既有 PR 的状态不能直接代表当前本地修复版本，Git HEAD 也不包含全部未提交修改。

### 2.2 语言与来源原则

测试问题和产品答案以英文为首要要求，技术标识、目标编号、文件路径、作者、日期及原始状态应保持准确。界面中已有中英文控件继续保留，本轮不等于全站界面英文化。

回答必须使用授权来源。明确选择的文档范围优先于推断元数据；资料未记录的内容不能被填成失败、零值或已完成。计划、会议演示、目标状态、交付记录与运行监控分别使用各自证据。

## 3. 测试设计与验收口径

### 3.1 G1 与 G2 的测试链路

| 模式 | 测试链路 | 重点检查 |
| --- | --- | --- |
| G1 / Fast | 提问 → `/api/chat/stream` → 检索 → 流式答案 → 保存与展示 | 英文正文、数字和实体、来源范围、引用支持、SSE 终止、历史操作 |
| G2 / Deep Research | 选择资料 → 冻结 SourceManifest → 创建任务 → 编辑/审批计划 → 检索与原文读取 → Evidence/Finding/Claim 核验 → 报告 | 计划契约、证据覆盖、状态语义、来源绑定、持久化、追问与下载 |
| 浏览器端到端 | 首页/聊天页操作 → 后端处理 → 真实页面与文件结果 | 功能入口是否接通、正文与引用是否可见、复制/刷新/下载是否真实完成 |

G1 与 G2 使用的执行和检索路径不同，不将两者笼统视为同一检索实现。

### 3.2 测试规模与判定

主测试集为 [18 道英文用例](../../eval/deep_research_a/datasets/cases.en.v1.json)。每题在两种模式下各重复三次，以 `(case_id, group, repetition)` 作为唯一验收坐标，总计 108 个坐标。另有日期与范围的六种问法变体，以及合成冲突、长问题、长标题和异常传输等回归控制。

判定分为四层：

1. **技术链路**：接口完成、任务终止、结果保存，不将 HTTP 200 自动判为答案正确。
2. **内容质量**：事实、数字、实体、周期、状态与问题相关性符合原文。
3. **证据质量**：来源在授权范围内，引用存在并支持对应陈述，原文和定位可核对。
4. **前端可用性**：结果可显示、复制、展开、刷新恢复或实际下载。

严格质量评分采用六维均不低于 4，且没有 unsupported claim 标记的门槛。评分作为辅助证据；有争议时人工逐项核对原文，并保留原始评分与复核理由。

验收台账汇总多轮真实执行记录，不作为单一冻结配置下的性能或稳定性比较。修复后的定向重试单独保留，历史失败不会被最终成功结果覆盖。相关子集、重复测试与全量回归的数量不累加。

## 5. 主要缺陷、修复措施与复测结果

### 5.1 研究入口、计划与审批

| 问题 | 修复措施 | 结果 |
| --- | --- | --- |
| 首页研究模式未完整连接实际任务 | 统一资料筛选、多选、冻结清单和研究创建；无资料时阻止提交；保留页面跳转后的模式 | 浏览器走通资料选择、创建、计划编辑、批准、执行和报告 |
| 研究注册重试与部分历史状态不一致 | 关联研究会话及消息序号，注册幂等，兼容部分注册状态 | 路由与历史回归通过，会话可重新读取 |
| 独立测试数据库缺权限账户表 | 补齐必要迁移与隔离测试表 | 登录、资料选择、研究注册及收藏读取已验证 |
| 长英文问题创建失败 | 保留完整 query，仅限制契约中 topic 字段长度 | 长问题回归通过，问题正文不被截断 |
| 长资料标题使计划验收字段超限 | 使用简洁目标，限制 target 长度；来源仍绑定 source_ids | 计划创建、保存及重新读取通过 |
| 英文审批/取消与控制接口不一致 | 识别英文命令，连接研究控制接口，保持错误提示语言一致 | 审批与取消有浏览器验证；取消未在最后阶段逐场景全部重测 |
| 联合验收条件被改写 | 保留 features + fixes 的联合条件和 fixes 上限，增加计划及答案检查 | `5 + 1 = 6 >= 6`、`1 <= 1`，结果 Pass |

### 5.2 流式展示、历史操作与持久化

- **引用组件吞掉正文**：将容易影响后续文本的 HTML 标记改为 inline Comark 引用组件。相邻引用、正文和复制结果均已核对。
- **编辑/重新生成失败**：统一 DELETE 的 message ID 路径和 chatId、操作类型请求体；SSE start 使用已保存的助手数据库 ID。仅对最后一条失败助手消息确实未落库的特定情况允许跳过 404，其他错误仍中止。
- **正常流被误判中断**：以响应连接关闭判断流式中断，区分请求 close、正常完成和真实断开；增加保存边界测试。
- **刷新后检索引用丢失**：持久化工具输出，复用引用和原文查看器，刷新后仍可读取来源。
- **长研究追问损坏事件历史**：进度 message 保存不超过 500 字符的摘要，完整回答保存在 payload.content，并兼容旧事件。实际 1,165 字符正文、末段复制与刷新保存已验证。
- **来源冲突选择逻辑不可达**：恢复正确分支，保存用户选择和独立报告版本；非法来源不修改报告，合法选择可持久化重新读取。选择操作本身不被视为证据重新核验。

### 5.3 检索范围、日期与跨文档覆盖

Fast 曾只召回项目汇总或单一时期资料，缺少所需模块和会议证据。修复采用有界子查询、模块/周期标题匹配、文档发现、交错合并和短文档读取，仍保留权限与显式文档范围交集。

编码标题增加日期识别，区分事件日期、资料快照日期和事实生效范围；覆盖 timeline、chronology、reconcile 等问法。相邻原文读取扩展至两侧各两个 chunk 并去重，避免半句或半个单词被作为完整证据。

明确选择的来源不再被推断的 topic/metadata 错误缩小。范围不明确的架构问题先澄清；资料不支持精确数字时拒绝给出假数字，而非借用相似模块的数据。

### 5.4 数字、模块与周期绑定

| 已观察错误 | 修复规则与正确结果 |
| --- | --- |
| 把项目总提交量当成 Agent 数量 | 以模块 metadata、周期和原文汇总字段绑定。W30 Agent 为 `9/5/1/3`，W34 为 `8/3/5/0`；对应差值 `−1/−2/+4/−3` |
| 表格比较只支持其中一周 | 每列绑定本周期来源，变化同时引用两期证据 |
| 模块合计冒充项目唯一总数 | 模块合计 26 与项目记录 23 分开，不直接相加替换 |
| 三周项目总数取到局部明细 | 摘要 Total Commits 优先读取；W28/W30/W34 为 `9/14/23`，变化 `+5/+9/+14` |
| Web 状态被写成 Standby | 读取 Master Overview 原始行：Agent 8、Web 18 为 Delivered；其他三个模块为 Standby、0 次 |
| 提交身份与模块错配 | 哈希、作者、日期、周期和模块同时绑定：query rewriter 为 `32559e07a`、fionaxi、2026-07-25，Agent 总数 9 |
| 把 Agent 数字贴到未授权 Web 问题 | 检查实体和授权来源，不支持时明确证据不足 |

解析来自实际来源字段，不将基准答案作为运行时证据。使用不同模块名、未来周期、不同数字及来源顺序变化的回归样例检查泛化与不一致拒绝。

### 5.5 目标状态、生命周期与综合报告

- 重复 M8/M9 等编号按“完整名称 + ID”绑定；不同命名目标不合并状态，空白保持 `not recorded`。
- 目标名称匹配增加非空校验和原始名称约束，避免空规范化名称匹配所有行。
- 完整 Skills System 与较小的 Skill Registry 分开处理，排除条款不能直接套到组件状态。
- 会议展示的问答到报告流程、Goals 中的状态和待办行动分别引用，演示不等于全部目标完成。
- 生命周期读取完整周表和 lifetime summary，去重并检查一致性；不把局部明细代替汇总。Data Pipeline lifetime 为 11、Toolset 为 20；Toolset 最忙周为 W27、11 次提交。
- 对资料未覆盖的 SLA、事故数和后续周次明确未知，不能由 Completed、提交数或资料未提及推断 99.9% 可用率、零事故或失败。
- 综合报告分离已演示能力、尚待处理的证据链接和可复用工具、评测优先级，去除重复描述；保留更具挑战的问题集和 5–10 个多样化问题的行动要求。

### 5.6 依据核验、局部修补与传输恢复

确定性检查先核对数字、目标行、生命周期、语言及范围，再补充语义审查。审查要求严格 JSON 和布尔类型，截断响应、字符串布尔值、虚构引述不能通过。

原文引述必须匹配实际来源。只有能唯一匹配真实引述时才恢复无效引用编号；空引述不能自动成为错误证据。报告局部修补限于唯一定位段落或表格块，不替换无关标题或整篇正文。修补失败保留旧候选；有界重新合成仍需通过结构和依据检查。

空流或只有推理没有正文时，仅在尚未向用户输出正文的前提下有限恢复；已输出部分正文不重放，避免重复答案。异常和供应商拒绝与普通质量拒绝分开记录，不把兜底提示计为正确答案。

### 5.7 下载与来源定位

研究报告下载接入 `GET /api/research/download`，核对登录状态与资源归属，在服务端使用 Agent token，并清理文件名和设置 private/no-store。浏览器实际获得 Markdown 文件，文件正文及 Sources 已读取核对。下载回归涵盖未登录、他人资源、非法 ID、成功内容和响应头。

来源展示保留 doc_id、source_url 和真实 locator；空 locator 回退 chunk_id。记录的外部 URL 不等于已验证访问权限，本地原文 200 也不证明登录后 Confluence 可达。

### 7.2 十八题覆盖内容

## 9. 本地前端运行维护

网页多次无法打开时，检查发现前端进程退出、3000 端口无服务；后端仍运行。应用错误日志未给出确定的退出原因，不能归因为主题修改或页面渲染错误。

先将临时进程改为独立隐藏后台宿主；后续仍观察到运行约半小时后退出，因此进一步增加运行诊断和恢复机制：

- 缓存 Windows 进程句柄，记录真实退出码、PID 和启动时间。
- 保存每次启动的独立 stdout/stderr，增加 boot、beforeExit、exit 及未捕获异常诊断。
- 进程退出后等待两秒再启动；连续五次快速失败则停止重试，避免无上限反复启动。
- 使用本地 stop 标记支持停止；保留原有数据库和稳定会话密钥。
- 仅监听本机回环地址，不扩大对外访问范围。

首次诊断加载因 Windows 路径转义失败，已修正并重新启动。之后模拟停止前端，宿主记录退出码 `−1`，自动启动新进程，网页重新返回 HTTP 200。该测试证明恢复机制可用，但不证明原始退出根因已解决，也不证明长期无人值守稳定性。

运行维护文件位于本地 `outputs`，不属于已提交的源码部署方案：

- `start-frontend-independent.ps1`：后台宿主与恢复逻辑。
- `frontend-exit-diagnostics.cjs`：退出诊断。
- `frontend.host.log`、`frontend.exit-diagnostics.log`：宿主和运行记录。

正式部署仍应使用明确的服务管理与持久化策略；本说明不把本地恢复脚本当作生产可用性验收。
