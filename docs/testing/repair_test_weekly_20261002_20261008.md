## 2. 测试对象、标准与证据口径

### 2.1 G1 与 G2 的含义

- **G1：普通 Fast 问答。** 在线评测使用前端对应的 `/api/chat/stream` SSE 路径，验证检索、回答、引用和终止事件。浏览器验证额外检查实际展示、复制、重生成及刷新保存。
- **G2：Deep Research。** 选择资料并冻结 SourceManifest，创建任务，生成计划，明确审批，执行检索与原文读取，形成 Evidence/Finding/Claim，检查覆盖和引用，生成报告，并验证原文、追问和持久化。

G1 与 G2 的检索后端和执行路径并不完全相同。测试记录实际配置，不能统一称它们均使用同一种 Milvus hybrid 路径。

### 2.2 本周采用的验收原则

1. 问题与答案以英文为首要要求；中文知识库中的名称需要在英文答案中合理表达，技术标识、文件路径、编号和状态不得随意改写。
2. **HTTP 200、日志 PASS、job completed 仅表示技术链路结果。** 报告内容仍可能错误、缺失、降级或只是兜底提示，必须单独检查。
3. 数字需要绑定具体模块、周期和来源；引用编号存在、来源在白名单内，并不自动证明引用支持那条事实。
4. 计划、目标、会议演示、历史状态、后续完成状态分别处理。空状态是 `not recorded`，资料未提及是未知，不能推断失败、缺失或已经解决。
5. 同模型评分保留作为辅助证据，人工原文核对优先。模型曾给错误或冗长答案高分，因此分数不能替代验收。
6. 失败记录、重试记录、模型切换和代码版本均保留；重复覆盖的测试数量不相加，不同模型的成绩不拼接成同一通过率。
7. 基准答案未作为运行时证据写入模型上下文。新增源驱动路径从实际来源解析字段，并使用其他模块、未来周期及不同数字的回归样例检查泛化。

### 2.3 数据集和运行边界

- 主测试集：[18 道英文用例](../../eval/deep_research_a/datasets/cases.en.v1.json)。每题有对应授权文档清单。
- 补充测试：[六种日期／范围措辞变体](../../outputs/full_qwen36_flash_20261007/variants.json)，包括 DATE-01～04、SCOPE-01～02。
- 合成冲突控制单独记录，用于同一生效版本的启用／禁用矛盾，不代表真实资料中一定存在该矛盾。
- 后期使用独立前端 `ui.db` 和研究任务数据库，服务仅监听本机回环地址。没有修改生产账号或实际企业系统。

### 4.3 报告引用、历史操作和持久化

**报告正文被引用组件吞掉。** 原始 HTML cite-mark 经 Comark 解析时将后续文字纳入引用组件，导致相邻引用后的句子不完整。改为 inline Comark 组件，浏览器核对连续引用和正文；复制出的正文也保留完整内容。

**编辑／重新生成失败。** 前端 DELETE 参数不符合路由契约；助手的 UI ID 与数据库 ID 也不一致。修复为 message ID 路径、chatId 与操作类型请求体；SSE start 显式使用已保存的数据库助手 ID。仅允许最后一条失败助手响应确实不存在历史行时跳过该 404；其他鉴权、并发或服务错误仍停止，避免破坏历史。

**正常流被误认为中断。** 请求 close 不代表响应流断开，改为响应连接 close，保留正常完成及真实中断的保存边界测试。实际编辑、重生成、刷新均有浏览器记录。

**刷新后普通问答引用丢失。** 保存 RAG 工具输出，复用引用组件和原文查看器；刷新后仍能展示正确的检索来源。

**长研究追问写坏事件历史。** 正文超过进度摘要 500 字符限制时，旧代码可能先存事件再校验失败。现在 progress `message` 只存摘要，完整正文存入 `payload.content`，前端显示和复制完整正文；兼容旧超长事件。真实测试取得 **1,165 字符**回答，数据库摘要 500 字符、正文 1,165 字符，末段复制和刷新均验证。

**冲突来源选择返回 None。** 报告修订代码曾错位到无条件 return 后，无法到达。恢复正确分支，生成独立报告 ID，保存用户选择、引用及原质量限制。错误来源不改报告，合法来源持久化后可重新读取。用户选择本身不等于证据重新核验。

### 4.4 英文输出、问题路由与检索覆盖

**英文问题返回中文降级、原始提交历史或多余标题。** 架构范围不明确时先给英文澄清；英文标题使用问题摘要，避免额外模型调用生成中文标题；收紧报告结构，减少无关历史倾倒。系统界面仍有中文控件，本周的英文首要要求主要针对问题、答案与评测材料，未声称全站完成英文化。

**Fast 检索被一个对象或项目 Master 占满。** 曾把 W30/W34 的项目总数 14/23 当作 Agent 总数，或者只召回七月计划而缺少九月会议。增加有界子查询、标题中的模块／周期匹配、文档发现、交错合并和短文档读取；保留显式文档范围和权限交集。

**显式来源被推断元数据覆盖。** 显式选择的文档清单优先，不能再由模型推断的 topic 或 metadata 缩小成错误范围。来源选择格式标准化，事实变更问题进入问答路径，避免错误触发无关工作流。

**编码标题中的日期无法识别。** 处理标题编码与日期解析，区分会议事件日期、文档快照日期和同一生效版本的事实范围。日期路径从只覆盖 `compare dates` 扩展到 timeline、chronology、reconcile 等常见措辞。

**原文分块边界截断。** 相邻读取扩大到两侧各两个 chunk，去除重叠；不把以半个单词开头的截断句当作完整原文观察。DATE04 最新 G2 核对到了完整早期依赖段落。

结果：最新数量题 G1/G2 正确回答 9/5/1/3 对 8/3/5/0；日期与范围变体已有增量复测证据。不能据此保证任意长文档或任意措辞都已覆盖。

### 4.6 目标编号、范围与状态

**重复目标 ID 混用状态。** 原文中同一个 M8/M9 编号可能对应多个名称。解析表头和命名列，以完整 goal name + ID 绑定；问题指定 Research Graph 时只选该名称，未指定名称的重复 ID 分开列出。空白不借邻行状态，也不自动补成 Not started。

**中文目标名匹配过宽。** 空的英文规范化名称曾导致所有行都被匹配。增加非空限定及原始名称校验；英文名称翻译必须保留技术词和行对应关系，模型只负责受约束名称翻译，不决定状态。

**完整 Skills System 与 Skill Registry 混为一谈。** 完整系统被明确排除，并不证明较小 registry/skill 也被排除；组件的 Not started 不能套给完整系统。分别引用排除条款和组件自己的 Goals 行，目标周明确标为计划，而非完成日期。

**会议演示被写成目标全完成。** 将会议中展示的问答→报告流程、Goals 中的 Finished/Not started/blank、尚需修复证据链接、可复用工具与后续评测优先级分别列出。演示成功不能证明所有组件完成，也不能把 action item 写成已完成。

结果：012、006、018、SCOPE01/02 有最新来源行核对和增量 G1/G2 复测。不同段落的相关状态不能替代问题要求的那一行。

### 4.7 生命周期统计与 SLA 未知状态

**生命周期只读到局部明细。** 017 曾漏掉 Toolset 周次，把最忙周 W27=11 写成 8，把 W32=4 写成 3；旧模型也可能写出 12 的局部合计。现在读取同文档的模块 metadata、完整 Sprint 表和 lifetime summary，去重重叠片段，校验表格总和与汇总一致；不同文档或冲突计数不拼接。所有显式非零周列出，最高值并列则保留并列，不将未列周猜为 0。

最新核对：Data Pipeline lifetime **11**，Toolset lifetime **20**；Toolset 最忙周 **W27，11 次提交**，对应汇总表引用。

**把 SLA 不可证明写成 SLA 失败。** W34 交付资料没有九月运营可用率、测量周期或事故数。代码现在明确回答 unknown，要求监控证据，不以 Completed、commit count、资料未提及来证明 99.9% SLA，亦不编造 0 事故。007 的 degraded 是证据边界下的预期结果，不是技术故障；实际正文已核对。

### 4.8 语义审查与局部修复

本周发现审查模型会误放行待办→完成错误，也会把“该陈述有支持”“不是缺陷”等自我纠正文案放入 issues，误触发降级。处理包括：

1. 系统规则与用户问题／冻结资料放在不同消息中；资料中的指令不升级为系统规则。
2. 严格审查 JSON 和布尔类型；字符串 `"true"` 不视为布尔 true，截断响应不能通过。
3. 原文引述必须匹配实际来源；无效引用编号仅在能唯一匹配实际引述时恢复，虚构引述拒绝。
4. 空引述不能自动成为错误证据，使用实际来源独立确认；无依据的审查失败不冒充正常答案。
5. 先运行数字、同源目标行、生命周期完整性、英语与范围等确定性检查，再使用模型补充语义检查。
6. 局部修补定位唯一段落／表格块，禁止用编辑参数替换整篇报告或修改无关标题；失败修补保留旧候选，不直接发布。
7. 两次局部修补不成功后，有界地从同一冻结证据重新合成，仍须通过结构和依据检查；必要时再做一次引用修补，不能越过门槛发布。
8. 在检查标题、段落和表格引用时处理格式差异，避免标题后少空行让未引用正文逃过检查；数字和状态需要真正支持它们的来源行。

这些措施减少了真实已观察缺陷，不代表模型审查可以达到零误差。以前的同模型高分、后来的安全降级以及最终正确答案均保留，不抹去历史失败。

### 4.9 模型服务、空流与预算

**只输出思考、不输出答案或空流。** 合适的 Qwen／DeepSeek 兼容客户端默认非思考，明确启用仍尊重。仅在没有向用户输出正文时做有限重试；空输出两次后允许同模型非流式恢复，部分正文已输出不能重放。额度 403 等确定拒绝不重试消耗。

**隐式思考耗尽预算。** 早期检查响应实际产生约 9,000～9,852 推理 token，造成超时；随后经历默认关闭和有界审查预算的实验。最终配置按代码明确控制，各阶段历史不同，不能拿早期单次耗时当最终模型速度。

**额度与兼容性中断。** 多个用户指定的模型返回 `insufficient_quota`。`qwen-mt-flash` 不支持当前所需 system 消息，不能继续通用问答／研究链路。先探测、再定向复测；不自动切换未授权模型，不把额度兜底输出算质量通过。

当前 `qwen3.5-27b` 已成功完成真实在线调用。只能说明该次调用时可用，不能保证之后额度仍充足。

### 4.10 下载、来源链接与计划字段边界

**下载没有实际文件证据。** 早期 blob 锚点点击后浏览器下载事件超时，不能只因按钮点击成功判通过。最终增加 `GET /api/research/download?researchId=...`：要求会话、研究会话归属，服务端持 Agent token 获取持久化 Markdown，传递相同用户身份；文件名清理，private/no-store，浏览器不接收 Agent token。实际点击取得下载文件，读取 **2,028 字符**，包含 `5 + 1 = 6` 和 Sources。下载接口回归覆盖未登录、他人资源、非法 ID、成功内容与响应头。

**将记录的 Confluence URL 说成已验证可访问。** URL 和 locator 是来源元数据；本地 source endpoint 200 不证明外部站点权限。最新 G1/G2 答案明确外部可达性未验证，同时提供真实链接、哈希、作者、日期和 chunk locator。这里修复的是不实断言，外部链接的实际可访问性仍未验收。

**来源顺序导致模块匹配失败。** 详细片段先于文档头时，之前只检查拼接文本开头可能错过模块／周期。改为优先匹配实际头信息，增加“明细在前、头在后”的异构测试。

**长来源标题生成超长验收字段。** fallback 英文计划拼标题后 `AcceptanceCriterion.target` 超过 200，写入后读取失败。初始中文构造使用简洁目标，英文转换也限制字段长度，来源绑定仍保留在 source_ids。长标题计划创建、持久化读取回归已通过；新的联合验收任务也可正常读取。
